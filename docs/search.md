## 対戦の記録係のやり方

1. 入力されたターンを、記録の出る Showdown で48通りの乱数で打ち直す。相手の型は「今いちばんありそうな型」にする。
2. 見えた結果に一番合う展開を選ぶ。比べるのは、どちらが先か、HP、急所、場の体、状態異常。
3. 能力ランク・天気・まきびしなどは、その展開から取る。
4. 見えた数字（HP、状態異常、場の体、メガシンカ）は入力の値で上書きする。
5. 画面の「今の状態」で直した値（能力ランク、天気、フィールド、トリックルーム、まきびし・壁など）でも上書きする。

推定に渡す手がかりは次のとおりです。

- 技・持ち物・特性：メガシンカ後の特性も認める。
- 順番：こちらのアンコールが先に当たったターンは使わない。
- 相手が受けたダメージ（%）：次のときだけ使う。
  - こちらが先に動いた（相手は動かなかった）。
  - 相手のHPがそのターンに他の理由で動かない。
  - みがわり・ばけのかわがない。
  - へんげんじざい・リベロを持ちうる種族ではなく、メタモンでもない。

- メガシンカの前の姿でダメージ・順番を計算していた。

## 弱点・残っていること

- i5-5300 の実機で、ターンの再現に何秒かかるかは確認していません。対戦中に画面の「再現○秒」で分かります。再現が長いほど探索の時間が減ります。
- 強さの確認は、相手の本当の型を知っている前提での比べです。推定を使った探索の強さと、指示文 4-5. の基準（2000試合以上）での比べは、段階6で行います。
- 盤面の評価は手作りで、重みは私が決めました（例：HPの割合0.5、状態異常−0.08）。段階6で、AIどうしの対戦で比べてから変えます。
- 相手の行動の予想は表示していません。仮の盤面ごとに相手の技の並びが違うため、まとめ方を作っていません。
- 記録係が追う一時的な状態は、盤面の形の8種類（みがわり、こんらん、やどりぎのタネ、ちょうはつ、こだわりの固定、あくび、きあいだめ、のろい）と姿の変化だけです。アンコール・かなしばり・タイプの変化などは、次のターンの盤面に残りません。
- 途中の交代（とんぼがえり・倒れた後）の交代先は、探索の中では無作為に選んでいます。
- 照合（tools/compare）は、同じ盤面の形から作った対戦どうしを比べます。そのため、盤面の形から対戦を作る部分そのもののずれ（上のメガシンカと天気の件）は照合では見つかりません。記録係の通しで見つけています。

## 入力を減らした変更（2026-11-28、利用者の承認：案A）

- 毎ターンいつも出す欄は、こちらの行動・相手の行動・HP（こちらの3体と相手の場の体の%）だけにした。
- 先に動いた側は両方が技を出したときだけ、メガシンカの欄はメガシンカできるときだけ出す。場の体は、行動の欄で選んだ交代から決まり、HP を0にしたときだけ「倒れた後に出した体」を選ぶ欄が出る。
- 急所・相手の持ち物と特性の発動・状態異常は「ほかに起きたこと」にまとめ、最初は閉じておく。状態異常は、触らなければターンの後の場の体の今の状態異常を引き継ぐ。
- 急所は、印をつけたときだけ「急所だった」とし、空なら「分からない」として、急所の確率（急所ランク0で1/24、ピントレンズ等で上がる。相手がシェルアーマー・カブトアーマーなら0）で急所と急所でない場合を混ぜて、ダメージの手がかりを計算する。
- 「保存せずに終える」ボタン（確認つき）を足した。

確かめ：
- 試合の模擬（乱数25・30、各20試合）で、急所を空にしても本当の型が消えた回数0。比べとして、急所だったのに入れ忘れて「急所ではない」と入った場合（乱数25、20試合）は23回消えた。
- 画面の確かめ（8ターン）：1ターンの操作は4〜8回（「記録して計算」を押す1回を含む。前は5〜8回）、毎ターン9.7秒、エラー0。保存せずに終えると準備の画面に戻り、今の対戦の記録が消え、保存した記録は増えない。

弱点：状態異常が変わったのに「ほかに起きたこと」を開かずに記録すると、前の状態異常のまま計算します。

## 入力の作り直し（2026-11-28、利用者の承認）

利用者の指摘：選出の60秒が長い。入力欄が小さく順番が悪い。入力が多くて時間が足りない。さめはだ・ステルスロック・すてみタックルの反動が考慮されていない（原因：ターンの後の HP の欄に前の HP が入ったままで、自分で直さないと減らなかった）。

- 選出の計算は既定45秒。6体を入れ終えてから、おすすめが出るまでで数える（打ちかけの試合の分として3秒残す）。
- 対戦の画面の並び：今の盤面 → おすすめの3手 → ① 相手の行動 → ② こちらの行動 → ③ 結果 → 記録して計算 → 相手の型の推定 → 今の状態（閉じておく） → 記録。

- 両方の行動を押すと、記録係がそのターンを相手の「いちばんありそうな型」で24通りの乱数で打ち（Analyzer.predict）、こちらの3体の HP（真ん中の値）、相手の HP%（真ん中の値）、先に動いた側、場の体、状態異常を予想して欄に入れる。反動・さめはだ・ゴツゴツメット・ステルスロック・いのちのたま・たべのこし等は Showdown が計算する。手で直した欄は上書きしない。

## 直したこと（2026-11-28、利用者の指摘：決着・死に出し・こちらの HP・交代）

- 死に出しを別の場面にした。こちらの場の体が倒れたら、ターンは「倒れたまま」で記録し、次に「死に出しの場面」を出す。そこで交代先を選ぶと、記録係が Showdown で交代させ（ステルスロック・どくびし等も Showdown が計算する）、その後に画面の HP で上書きする。前は、記録係の再現が交代先を勝手に（番号の若い体を）選んで出していた。そのためステルスロック等のダメージが別の体に入り、こちらの HP が勝手に動いて見えた。
- 死に出しの判断：倒れた体を交代先を選ぶ要求（Showdown と同じ switchFlag）にして探索するので、死に出しの場面で「どの体を出すか」の上位3手と勝率が出る。
- 決着：こちらが全員倒れたか、相手が3体倒れたら、死に出しの場面を出さずに決着の欄（勝ち負けは自動で入る）を出す。前は決着した後も死に出しの場面と判定していた。
- 交代の反映：行動で交代を選ぶと、ターンの後の場の体の欄を交代先にそろえる。とんぼがえり・ドラゴンテール等で場の体が変わったときも、予想した場の体を入れる。場の体の欄は選び直せる。
- 相手の控えの HP：%→実数→% の行き来で1ずつ減っていくことがあった。取り直すのは、そのターンに場にいた体だけにした。
- どくびし・ステルスロック：Showdown が計算する。画面の状態異常の欄は、触っていなければ予想（どくびしで毒になった等）を入れる。前は触っていない欄の「なし」が毒を消していた。
- 確かめ：Node で本当の対戦を決着まで打ち、毎ターン・毎回の死に出しの後に記録係と比べる道具（tools/battle/flow-check.ts）で、70試合ずれ0（場の体・こちらの3体の HP・相手の HP%・倒れたか・死に出しの場面・決着）。ブラウザで同じことを画面の操作で行う道具（tools/browser/flow-e2e.ts）で、計7試合（ターン 82 ほか）ずれ0、ページのエラー0、1ターンの操作の平均4.1回。

弱点：記録係が追っていない状態（技の固定、アンコール等）は、まだ再現に入っていない。i5-5300 での時間は確認していない。

## 直したこと（2026-11-28、利用者の指摘：交代技・先手後手）

- 交代技（ボルトチェンジ・とんぼがえり・フリップターン等）の予想：前は、交代先をいつも番号の若いポケモンにし、先手の場合と後手の場合の HP を混ぜて中央値にしていた。交代先（ターンの後の場のポケモン）や先に動いた側を画面で直すと、その条件で予想し直す。先に交代技を打てば相手の攻撃は出てきたポケモンが受け、後に打てば下がる前のポケモンが受ける（test/predict.test.ts）。決めた順にならない相手の型しか推定していないときは、その順になる型の中でいちばんありそうな型で予想する。
- 「動けなかった」（ねむり・ひるみ・先に倒された等）側があるターンの予想：前は、その側に行動を渡さず、Showdown が選択を待ったままターンが進まず「何も起きない」予想になっていた。記録と同じく選べる行動の最初を渡し、その側が技を出した乱数は使わない。
- こちらが倒れたターンの予想で、交代先を勝手に出していた（出てきたポケモンにステルスロック等のダメージが入った予想になっていた）。こちらの交代先は死に出しの画面で選ぶので、予想では出さない。
- 記録の作り直しで、こちらと相手の行動を「文字列にして」選べる行動と比べていたため、画面の入力についている「mega: false」の印だけで一致せず、いつも1番目の技で作り直していた。HP・場のポケモン・状態異常は画面の値で上書きするので見えなかったが、能力ランク・まきびし類・こだわりの固定等がずれていた。形で比べるように直した。
- 死に出しの記録で、盤面の状態を当てない対戦（まっさらな対戦）で交代させていたため、死に出しの後に、まきびし類・天気・能力ランク・こだわりの固定が消えていた。状態を当てた対戦で交代させる。
- 死に出しの盤面で、Showdown が交代の後にターンの終わりの処理（すなあらしのダメージ・たべのこし等）をもう一度行っていた（sim/battle.ts の turnLoop は、ターンの途中の印 midTurn がないとターンの始めと終わりの処理を足す）。死に出しの盤面ではターンの途中の印を立てる。
- 記録の作り直しの選び方：「動けなかった」側が技を出した作り直し、入力では倒れていないのに倒れた作り直し（HP の差は小さくても、倒れると能力ランクが消える）、控えにいた相手が倒れた作り直しに罰点をつけた。控えにいた相手を作り直しから倒れたことにしない。
- 確かめ：Node の流れの確かめ（tools/battle/flow-check.ts）に、交代技を選ぶ割合（引数3）と、画面で「今の状態」を直さない使い方（NOVIS=1。見えている状態の本当の値を渡さず、まきびし類・壁・天気・フィールド・能力ランク・こだわりの固定を本当と比べる）と、予想の確かめ（PRED=1）を足した。

  - NOVIS=1 の30試合（517ターン）：まきびし類・壁のずれ 221 → 0、相手の能力ランク 57 → 39、天気・フィールド 27 → 32、こだわりの固定 14 → 16、こちらの能力ランク 4 → 14（直す前は相手の行動がいつも1番目の技だったので、数え方の条件が違う。直した後の残りは下の弱点）。
  - 予想（PRED=1、517ターン）：HP が変わる・変わらないを外したターン 20 → 19（直す前の「何も起きない」予想は、別の確かめで 137ターン中 20 → 2）。

弱点：画面で「今の状態」を直さないと、推定した相手の型が本当と違うために、次のずれが残る。こだわりの固定（推定がこだわり系の持ち物）、天気・フィールド（推定の特性がすなおこし等、または本当はサイコメイカーなのに推定にない）、能力ランク（追加効果の乱数、推定の特性いかく等）。「特性の表示が出なかった」ことを手がかりにする仕組みはない。
