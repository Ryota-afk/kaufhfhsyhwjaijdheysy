## 表の1マスに使う AI を決めた測定

指示文の過去の実装の情報はないため、AI の強さで表の値がどれだけ変わるかを測ってから決めた（tools/select/fidelity.ts、fidelity-report.ts）。
利用者のチーム2 対 M-7 の1位の構築で、決まった24マスを、それぞれ40試合ずつ打った。AI は1手ごとに探索を回す回数だけを変えた（両者とも型は分かっている前提）。

| 比べた回数 | マスの勝率の差の平均 | 相関 | 差の大きさ（誤差で割った2乗の平均。偶然だけなら約1） |
|---|---|---|---|
| 25 と 100 | 0.147 | 0.743 | 3.49 |
| 100 と 400 | 0.098 | 0.868 | 2.05 |
| 25 と 400 | 0.182 | 0.569 | 9.29 |

1試合の時間（この計算機、1スレッド。4つ同時に動かしたときの値）：回数25 0.27秒、回数100 1.27秒、回数400 7.04秒。

決めたこと：**回数100** にした。25は400との違いが大きすぎる（相関0.57）。400は100の約5.5倍の時間がかかり、上位構築199件を埋めるのに見積もりで数か月かかる。100と400の間にも、偶然より大きい違いが残っている（上の表の2.05）。

## 表の埋め方（先回りの計算）

1. 全部のマス（3600）を4試合ずつ打つ。
2. 今の表で釣り合いを解き、確率1%以上で使われる行と列を出す。その行の全部の列と、その列の全部の行（答えを左右するマス）を16試合まで、次に32試合まで増やす。毎回解き直す。
3. 全部満たしたら、その構築は終わり。

- 3分ごとと区切りの時に、data/precomputed/<パーティの番号>/<構築の順位>.json に保存する。次の回はその試合数から続ける。試合の乱数の種は「構築・マス・そのマスの何試合目か」で決めるので、続きから打っても同じ試合を繰り返さない。
- パーティの6体の型を変えたとき、または AI の設定を変えたときは、その表を作り直す（名前や「よく使う」の印を変えただけでは作り直さない）。
- GitHub Actions：6時間ごと（世界標準時 3:47・9:47・15:47・21:47）に、12の分担を並べる（それぞれ論理4コア。2026-11-27 の実行記録で確認）。1回300分で区切る（2026-11-28 に利用者の承認で、1日1回・4つ・320分から変えた）。分担ごとに別の構築を受け持ち、終わったら保存して main に送る。12が終わった後に、表の一覧（index.json）と相性の見積もり（model.json）を1回だけ作る。サイトはその後に公開し直す。
- Actions の速さ（2026-11-27）：4分×2回の実行では、1試合あたり1.9秒（1位の構築）〜4.5秒（7位の構築）（1コアあたり）。320分の実行では、1位の構築が1分あたり約84試合（1コアあたり1試合約2.9秒）。この計算機（1.27秒）より遅く、構築によって2倍以上違う。
- 途中から再開（Actions）：1回目 4分で1位の構築を541試合まで保存。2回目の記録に「始める：チーム2 対 1位（保存済みの試合 541）」と出て、1035試合まで進んだ。4つの分担が同時に保存しても、取り込み直して送り直す処理が働いた。
- 1構築あたりの量の見積もり：全部のマス4試合で14400試合、答えを左右するマスが約700なら32試合で約2.2万試合、合わせて約3.7万試合。実際の表では、答えを左右するマスは約900〜1150だった（1位〜7位）。これを32試合まで増やすと1構築で約4.5万試合になり、Actions の速さでは1つの分担で1構築に約9〜15時間かかる。4つ並べて1日1回のときは、1日に約2構築だった（2回の実行で約22万試合、1構築約6万試合）。12並べて1日4回にしたので、1日に約20構築の見込み（上位199構築を全部埋めるには約10日。順位の高い構築から埋める）。この見込みは確認していません。

## その場の計算（対戦の準備の画面）

- 相手の6体が上位構築のどれかと同じ（並びは問わない）で、今のパーティの表が保存されていれば、それを読んですぐ出す。相手の型はその構築の型とみなす。
- なければ、保存した表から学んだ相性でマスを見積もり、決めた時間（既定60秒、選出時間90秒の中）だけ、答えを左右するマスに試合を足す。相手の型は、最初の型の候補でいちばん重いもの。
- こちらの確率のとおりにくじを引き、3体と先発を準備欄に入れる。選び直してよい。

## 弱点・残っていること

- 表のマスの AI は、両者が相手の型を知っている前提で、探索も100回だけです。人どうしの対戦の勝率とは違います。回数400とも、偶然より大きな違いがあります。
- 1マス32試合の誤差は、勝率0.5のとき約±0.09（標準誤差）です。確率の小さい選出は、この誤差で入れ替わることがあります。
- 相性の見積もりは、種族どうしの足し算です。型の違い、3体の組み合わせの相性は表しません。本当の対戦の表での当たり具合は、表が増えてから確かめます。
- その場の計算は、i5-5300 では60秒で約30試合の見込みです（この計算機の速さからの見積もりで、確認していません）。表のない構築では、ほぼ相性の見積もりだけで決まります。
- 表のない相手の型は「いちばん重い候補」の1つだけで打ちます。型の候補がない種族の技は、型データの技の候補の先頭4つです。
- 相手の選出の傾向（selections_m7.json）は、釣り合いの計算には使っていません（指示文のとおり、相手も読んでくる前提）。
